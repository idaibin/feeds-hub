# Content Format

本文件定义 feed Markdown 的 frontmatter、标题、摘要和正文。海报字段与图片文件关系只看 `docs/rules/poster-spec.md`。

## Principles

- 1 feed = 1 event。
- 只写已核验来源支持的事实。
- 明确主体、动作、时间、状态和来源。
- 用 `eventKey` 去重；同一事件的新状态必须能和旧状态区分。
- 不完整事实用低确定性表达。
- 正文优先 2 段，最多 3 段。

禁止：

- 观点化、预测化、标题党。
- “重磅”“史诗级”“影响深远”“这意味着”等判断。
- 投资建议、赛事预测、产品成功判断。
- 把社交热度当事实。
- 多个事件拼成一条。

## Frontmatter

必须符合 `src/content.config.ts`。

- `date`：写入时间。
- `eventAt`：来源标注的事件时间或新闻发布时间；新增内容优先 UTC ISO datetime（`Z` 后缀），页面按 `Asia/Shanghai` 渲染。
- `eventKey`：稳定去重键。
- `coverStatus`：`generated_webp` 或 `pending`。
- `cover`：站点路径，规则见 `docs/rules/poster-spec.md`。

## Title

只写核心事实。

```text
主体 + 动作 / 状态 / 结果
```

示例：

```text
OpenAI 发布新模型接口更新
Rust 项目发布 1.x 版本
某指数收盘上涨，芯片板块走强
某队晋级下一轮
```

## Subtitle

补充来源、范围、时间或状态，不写判断。

```text
官方公告显示，该更新已面向开发者开放
Reuters 报道称，相关决定仍待正式文件确认
比赛结束后，官方赛程显示下一轮对阵已确定
```

## Summary

一句话说明事实和当前状态，优先不超过 80 个中文字符。股市内容可以加入市场情绪。

```text
官方公告显示，该项目发布新版本，更新范围包括 CLI、配置和文档。
Reuters 报道称，相关政策仍在讨论阶段，正式文件尚未公布。
A 股收盘分化，芯片板块偏热，地产和消费板块偏冷。
```

## Body

默认 2 段：

```text
第一段：事实。
第二段：当前状态、市场情绪、赛程节点、可确认范围或待确认信息。
```

必要时第 3 段写来源差异、尚未确认信息或已排期节点。

长度建议：

- 每段 1 到 2 句。
- 单条正文控制在 120 到 260 个中文字符。
- 长背景、深度分析和观点内容放到 blog，不放到 feed。

## Category Rules

### `worldcup`

写赛事事实。正文必须覆盖当前可核验状态之一：赛前前瞻、比赛进程、结果。

- 第一段：比赛状态、对阵、时间、比分、关键节点或官方状态。
- 第二段：阶段、下一场、下一轮、分组、晋级淘汰或待确认赛程。
- 禁止预测、情绪化胜负判断和无来源阵容传闻。

### `lol`

写赛事和官方竞技事实。正文必须覆盖当前可核验状态之一：赛前前瞻、比赛进程、结果。

- 第一段：赛程、进程、赛果、阵容、规则或官方公告。
- 第二段：分组、晋级、下一场、版本状态或待确认信息。
- 禁止训练赛传闻、胜负预测和无来源选手状态判断。

### `stock`

写市场事实，可以加入市场情绪。

- 第一段：市场、指数、公司、政策、财报或宏观数据事实。
- 第二段必须包含 `市场情绪：上涨 / 下跌 / 分化 / 震荡 / 偏热 / 偏冷`，并说明对应板块或资产。
- 第三段可写风险提示或未确认数据口径。
- 禁止买卖建议、收益判断、目标价和无时间戳价格描述。

### `ai`

写发布、研究、产品、工具或政策事实。

- 第一段：主体发布、更新、论文、政策或工具变化。
- 第二段：开放范围、版本状态、适用对象、来源状态或待确认信息。
- 禁止 AGI 判断、能力夸大、无上下文 benchmark 结论和未核验路线图。

### `global`

写综合新闻事实。

- 第一段：地点、机构、主体、动作和时间。
- 第二段：确认措施、影响范围、公开文件或未确认信息。
- 禁止阴谋化解释、情绪化描述和无来源伤亡或损失数据。

### `rust`

写工程事实。

- 第一段：项目、版本、RFC、crate、工具链或安全公告。
- 第二段：变更范围、受影响组件、迁移要求、修复状态或文档位置。
- 禁止无证据性能判断、泛泛称“更快/更安全”和无来源采用规模。

### `product`

写产品事实。

- 第一段：产品、公司、功能、定价、平台规则或页面变化。
- 第二段：上线范围、用户可见变化、适用对象、公开页面或待确认信息。
- 禁止脱离事件的产品建议、成功学判断和无来源收入/用户数。

## Uncertainty

可写：

```text
目前官方文件尚未公布。
该信息来自媒体报道，仍需等待官方确认。
公开页面尚未显示完整范围。
不同来源对时间表表述不一致。
```

禁写：

```text
基本可以确定。
大概率会发生。
很可能带来巨大变化。
```

## Frontmatter Linkage

- `title` 写核心事实。
- `subtitle` 写来源、状态或范围。
- `summary` 写一句事实摘要。
- `priority` 只用于排序。
- `tags` 只保留实体、主题和类型，不写情绪标签。

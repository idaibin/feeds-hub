# Feed pagination recovery — Feature Spec

本规格只定义信息流分页失败后的用户可见行为。它不定义 API、数据库、迁移、自动重试或 Production 行为。

## Confirmed（已确认）

- 下一页请求失败时，保留当前已经加载的全部 cards，不清空、不回退。
- 失败态显示 `加载失败，请重试。`，并提供操作 `重试`。
- 只允许用户手动重试；失败后不得自动重试。
- `重试`必须请求同一个未成功的下一页，不跳页、不重新从第一页开始。
- 重试成功后清除错误状态，保留已有 cards，并继续分页流程。
- 只有成功确认确实没有更多数据时，才显示 `没有更多了`。
- 请求失败不是“没有更多数据”；失败态不得显示 `没有更多了`。

## 委派边界

- 下一页触发方式、错误提示、`重试` 的布局和加载中视觉表现由
  [`ui-spec.md`](./ui-spec.md) 定义。
- 重试请求期间的重复操作保护和焦点处理由 UI 规范与实现共同保证。
- 不同失败类型的区分、错误记录/埋点和服务端错误文案。
- API 如何表达“还有更多”或“确实没有更多”，以及相关契约、数据库和迁移状态。
- Production 发布、回滚和真实流量结果。

这些委派事项不能改变核心结果：失败保留 cards、手动重试同一页、成功后恢复、仅在确有无更多时结束。

## 主流程

1. 用户浏览已加载的 cards，并触发加载下一页。
2. 下一页成功：保留已有 cards，按列表顺序加入本页 cards；若仍有后续内容，继续等待下一页触发。
3. 下一页成功且确认没有更多数据：停止继续加载，并显示 `没有更多了`。
4. 下一页失败：保留失败前的 cards，显示 `加载失败，请重试。` 和 `重试`，不进入结束态。
5. 用户选择 `重试`：再次请求同一个下一页。
6. 重试成功：清除错误提示和操作，按成功结果继续第 2 步或第 3 步。
7. 重试再次失败：cards 保持不变，错误提示和 `重试` 保持可见；仍不显示 `没有更多了`。

## 失败 / 重试规则

| 状态 | 已加载 cards | 用户可见状态 | 下一步 |
| --- | --- | --- | --- |
| 下一页请求中 | 保持不变 | 不改变已加载内容 | 等待结果 |
| 请求失败 | 保持不变 | `加载失败，请重试。` + `重试` | 仅用户手动重试同一页 |
| 重试成功且还有内容 | 保持并追加 | 清除错误 | 继续分页 |
| 重试成功且无更多 | 保持并追加（如有） | 显示 `没有更多了` | 分页结束 |

## 可观察验收

以下场景均从用户可见列表行为判断，不以实现细节替代验收：

- **保留内容**：已有多张 cards 时让下一页失败；失败前后的 cards 数量、顺序和内容一致。
- **错误提示**：失败后可见准确文案 `加载失败，请重试。` 与操作 `重试`；此时不可见 `没有更多了`。
- **不自动重试**：失败后保持页面不操作，未出现新的下一页加载结果；只有选择 `重试` 才再次尝试。
- **同页恢复**：选择 `重试` 后，成功结果对应此前失败的同一下一页；已有 cards 保留，新 cards 接在其后。
- **成功清错**：重试成功后，错误文案和 `重试` 消失，分页按结果继续。
- **真正结束**：只有成功结果确认没有更多数据时出现 `没有更多了`；失败、等待或未确认状态均不显示它。
- **重复失败可恢复**：再次失败不会丢失 cards，也不会变成结束态，用户仍可手动 `重试`。

## 范围边界

包含：列表分页的失败保留、手动重试、同页恢复和无更多结束态。

不包含：API 设计、数据库、数据迁移、自动重试、Production 部署或发布验收。

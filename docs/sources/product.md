# Product Sources

## Category

`product`

## 信息目标

产品主题优先获取与产品变化、用户体验、增长、商业化和工作流有关的公开事实，不写脱离事件的泛泛建议。

关注：

- 产品发布、功能更新、定价变化、商业模式变化
- 用户旅程、onboarding、转化漏斗、设计系统、交互模式
- App Store、Chrome Web Store、官网、文档、changelog 的公开变化
- 创业公司策略、平台规则、创作者工具、开发者生态
- 增长实验、产品包装、用户反馈和运营信号

## 优先来源

1. 公司官方博客、产品公告、changelog、release note、帮助文档。
2. 官网、定价页、产品页、开发者文档、公开路线图。
3. App Store、Google Play、Chrome Web Store、Product Hunt 等公开产品页。
4. 创始人或团队成员的正式说明，前提是能对应到产品事实。

## 次级来源

1. TechCrunch、The Verge、Wired、Fast Company、Lenny's Newsletter、Stratechery、Every 等产品和商业报道。
2. 设计团队案例、工程博客、增长复盘、公开访谈。
3. 用户社区讨论，必须能回到真实产品变化或可截图验证的页面变化。

## 可参考热度来源

只用于判断关注度：

- Product Hunt 排名和评论
- App Store 排名和评价变化
- 社交平台讨论量
- 用户反馈密度
- 开发者或创作者社区采用情况
- 公开指标、等待名单、下载量或社区活跃度

## 禁止来源

- 没有产品事实的鸡汤式创业文章。
- 只讲观点、不提供案例或来源的产品方法论。
- 无法核验的收入、用户数或增长截图。
- 夸大商业结果的宣传内容。
- 与具体产品事件无关的模板化建议。

## 时间窗口

- 产品发布、功能更新、定价变化：发布后 72 小时内优先。
- 产品案例、增长复盘：发布后 7 天内优先。
- 长期产品趋势：必须有明确新证据、新页面、新数据或新讨论节点。

## 热度判断

产品内容判断是否写入看：

- 是否有明确产品变化或公开事实。
- 是否对产品设计、增长、商业化或用户体验有参考价值。
- 是否被用户、开发者、创作者或行业媒体关注。
- 是否能沉淀为可复用的产品观察。

## 跳过规则

- 只有泛泛建议，没有具体产品或事件。
- 只有观点，没有公开证据。
- 同一发布、定价或设计变化已写入，没有新增事实。
- 内容更适合长文博客，不适合短周期信息流。
